# Stitch 구현 계획서

2026-11-21

> 이 파일은 구현 계획서의 사본입니다. 화면 설계와 프로토타입으로 가는 링크는 공개 저장소에 두지 않으려고 뺐습니다. 그림 두 개(단계별 범위, PDF 읽기 흐름)는 원본 문서에서 봅니다.

## 요약

Stitch는 뜨개 도안 PDF를 올리면 기호 도안, 3D 모형, 단계별 안내가 있는 따라 뜨기 페이지를 만들어 주는 웹 서비스입니다. 구현은 로컬에서 끝까지 돌아가게 먼저 만들고, 그 뒤에 Vercel에 올립니다.

이번 계획에서 정한 것은 다섯 가지입니다.

- **대바늘 먼저, 코바늘은 두 번째.** 데이터 모델은 처음부터 두 공예를 모두 담게 설계합니다.
- **게이지는 선택.** 재서 맞추거나, 재지 않고 도안 숫자 그대로 뜹니다. 건너뛴 사람도 나중에 다시 맞출 수 있습니다.
- **LLM은 읽기만.** LLM은 도안 글을 구조화하는 데만 씁니다. 코 수 검산, 기호 도안, 3D, 게이지 계산은 코드가 합니다.
- **유료는 마네킹 꾸미기만.** 도안 읽기, 3D, 기록, 게이지는 무료입니다.
- **도안은 올린 사람만 봄.** 만들어진 페이지에는 공유 링크를 만들지 않습니다.

참고 자료는 두 가지입니다. 화면은 디자인 캔버스에 있고, 지금까지 만든 동작하는 예시는 바라클라바 프로토타입 페이지입니다.

## 사용자 흐름과 화면

사용자는 PDF를 올리고, 읽은 내용을 확인하고, 게이지를 맞추거나 건너뛴 뒤, 작업 화면에서 따라 뜹니다. 화면 10장은 디자인 캔버스에 있고, 아래 표의 이름을 누르면 해당 화면으로 갑니다.

| 화면 | 사용자가 하는 일 | 구현할 때 지킬 것 |
| --- | --- | --- |
| 랜딩 | 서비스를 이해하고 PDF 올리기를 시작 | 로그인 없이 보이는 정적 페이지 |
| 도안 올리기 · 읽는 중 | PDF를 올리고 읽는 단계를 지켜봄 | 변환 작업의 단계 상태를 그대로 보여 줌. 창을 닫아도 계속 진행 |
| 읽은 내용 확인 | 검산 결과를 보고 애매한 곳만 고침 | 단을 누르면 원문 위치 강조. 고치면 바로 다시 검산 |
| 게이지 맞추기 | 재서 맞추거나, 재지 않고 도안 숫자 그대로 뜨기를 고름 | 두 선택지를 같은 크기로 보여 줌. 건너뛰어도 나중에 다시 맞출 수 있음 |
| 작업 화면 | 3D와 기호 도안을 보며 뜨고 기록 | 프로토타입 페이지의 기능을 모두 옮김 |
| 마네킹 꾸미기 | 얼굴형, 피부 톤, 머리, 안경을 골라 봄 | 골라 보기는 무료, 저장은 플러스 |
| 요금제 | 무료와 플러스를 비교 | 가격과 변환 개수는 아직 미정 |
| 내 도안 | 올린 도안과 진행률을 봄 | 대바늘과 코바늘을 구분해 표시 |
| 휴대폰 작업 화면, 게이지 | 뜨면서 한 손으로 기록 | 기록 버튼과 단 올리기는 엄지가 닿는 아래쪽에 둠 |

이번에 캔버스에서 바뀐 것은 두 가지입니다. 도안 올리기와 내 도안 화면에 코바늘이 들어갔고, 게이지 화면 맨 위에 "재지 않고 도안 숫자 그대로 뜰게요" 선택지가 생겼습니다.

## 시스템 구조와 기술 선택

바깥 서비스는 모두 어댑터 뒤에 둡니다. 로컬에서는 설치 없이 돌고, Vercel에서는 관리형 서비스로 바뀝니다.

| 영역 | 로컬 | Vercel 배포 | 메모 |
| --- | --- | --- | --- |
| 웹 앱 | Next.js(App Router), TypeScript, React | 같음 | 화면과 API를 한 저장소에 둠 |
| 3D | three.js | 같음 | 프로토타입의 매핑 코드를 옮김 |
| 데이터베이스 | Postgres. 내장형(PGlite) 또는 Docker | Marketplace의 Postgres (예: Neon) | 로컬과 배포가 같은 SQL 방언을 씀. ORM은 Drizzle 후보이고, PGlite 조합은 M0에서 확인 |
| 파일 저장 | `./data/uploads` 폴더 | Vercel Blob 비공개 스토어 | PDF 원본을 둠 |
| 긴 작업 | Workflow SDK의 Local World | Vercel Workflows | PDF 변환은 요청 하나로 끝나지 않음 |
| LLM | Claude API | 같음 | PDF 입력과 JSON 스키마 출력을 씀. 모델은 M2에서 정함 |
| 로그인 | 고정 사용자 1명 (`AUTH_MODE=local`) | 미정 | M4에서 정함 |
| 결제 | 가짜 결제 스위치 (`BILLING_PROVIDER=mock`) | 미정 | M4에서 정함 |

이 선택의 근거는 세 가지입니다.

- Workflow SDK는 `'use workflow'`와 `'use step'`으로 단계를 나누는 오픈소스 라이브러리입니다. 같은 코드가 로컬에서는 설정 없이 돌고, Vercel에서는 Vercel Workflows가 실행합니다 ([Vercel Workflows 문서](https://vercel.com/docs/workflows)).
- Vercel은 파일을 Blob의 공개 또는 비공개 스토어에 두고, 관계형 데이터베이스는 Marketplace의 Neon 같은 제공자로 연결합니다 ([Vercel Storage 문서](https://vercel.com/docs/storage)).
- Claude API는 PDF를 직접 받고, 응답을 JSON 스키마에 맞게 제한할 수 있습니다 ([PDF support](https://platform.claude.com/docs/en/build-with-claude/pdf-support), [Features overview](https://docs.anthropic.com/en/docs/build-with-claude/overview)).

## 도안 데이터 모델

도안은 JSON 문서 하나(패턴 IR)로 저장하고, 검산과 모든 화면은 이 문서에서 나옵니다. LLM은 이 문서를 채우는 일만 하고, 대바늘과 코바늘이 같은 틀을 씁니다.

```ts
type Pattern = {
  craft: 'knit' | 'crochet'
  terms: 'kr' | 'us' | 'uk' | 'jp'        // 약어 체계
  title: string
  materials: { kind: string, spec: string, qty?: string }[]
  gauge: { stitches: number, rows: number, over_cm: 10, in_stitch: string, tool_mm: number } | null
  finished: { width_cm?: number, height_cm?: number }
  sections: Section[]
  finishing: { name: string, text: string }[]
}

type Section = {
  id: string
  name: string                             // 고무단, 머리 뜨기
  shape: 'flat' | 'round' | 'spiral'
  start: { kind: 'cast_on' | 'chain' | 'ring' | 'continue', count: number, from?: string }
  multiple?: { of: number, plus: number }  // 무늬 반복 단위. 게이지 재계산이 지킴
  groups: RowGroup[]
}

type RowGroup = {
  rows: Row[]
  repeat: { times: number } | { until_cm: number, from: string }
}

type Row = {
  side: 'RS' | 'WS' | 'round'
  ops: Op[]
  expect_count?: number                    // 도안에 적힌 코 수. 검산 기준
  text: string                             // 원문 지시문
  source?: { page: number, box: [number, number, number, number] }
}

type Op =
  | { st: string, n: number, into?: 'next' | 'same' | 'space' }
  | { repeat: Op[], times: number }
  | { repeat: Op[], until: 'end' | 'marker' | { remaining: number } }
  | { marker: 'place' | 'slip' | 'remove' }
```

코의 뜻은 IR 밖의 코 사전에 둡니다. 엔진은 사전의 "쓰는 코 수"와 "만드는 코 수"로 검산하고, 그리는 쪽은 같은 사전의 기호와 뜨는 법을 씁니다.

| 코 | 공예 | 쓰는 코 | 만드는 코 | 메모 |
| --- | --- | --- | --- | --- |
| k 겉뜨기 | 대바늘 | 1 | 1 | 안면 단에서는 안뜨기로 보임 |
| k2tog | 대바늘 | 2 | 1 | 오른쪽으로 기움 |
| yo 바늘비우기 | 대바늘 | 0 | 1 |  |
| sk2p (3코 모아뜨기) | 대바늘 | 3 | 1 |  |
| m1l, m1r | 대바늘 | 0 | 1 | 코 사이 가로실에서 늘림 |
| sc 짧은뜨기 | 코바늘 | 1 | 1 |  |
| inc (한 코에 2번) | 코바늘 | 1 | 2 | `into: 'same'` |
| sc2tog | 코바늘 | 2 | 1 |  |
| ch 사슬 | 코바늘 | 0 | 1 | 단 시작의 기둥코를 코 수에 넣는지는 도안마다 다름 |

길이로 적힌 반복(`until_cm`)은 게이지로 단수를 추정합니다. 확인 화면은 이 구간을 노란색으로 표시하고 사용자가 단수를 고칠 수 있게 합니다.

## PDF 읽기 파이프라인

LLM은 PDF를 IR 초안으로 바꾸는 일만 하고, 그 결과는 엔진 검산과 사람 확인을 거쳐야 페이지가 됩니다.

> (그림: PDF 읽기 흐름 · 7단계, 검산 되먹임 1개. 원본 문서에서 봅니다.)

검산에서 어긋난 단은 LLM에 되돌려 고치게 하고, 정해 둔 횟수를 넘기면 "확인 필요"로 표시해 사람에게 넘깁니다.

1. **올리기.** PDF를 비공개 저장소에 두고 변환 작업을 시작합니다. 같은 파일을 다시 올리면 이전 결과를 씁니다.
2. **꺼내기.** 쪽별 글과 글자 위치를 뽑습니다. 확인 화면에서 원문 위치를 강조하는 데 씁니다.
3. **LLM 구조화.** PDF를 그대로 LLM에 주고 IR JSON을 받습니다. 호출은 두 번으로 나눕니다. 첫 번째는 공예 종류, 약어 체계, 준비물, 게이지, 구간 목록이고, 두 번째는 구간별 단 지시문입니다.
4. **엔진 검산.** IR을 한 코씩 따라가며 코 수를 계산하고, 도안에 적힌 코 수와 비교합니다.
5. **되먹임.** 어긋난 단, 도안에 적힌 코 수, 계산된 코 수를 LLM에 돌려주고 그 구간만 다시 받습니다.
6. **사람 확인.** 길이로 적힌 구간, 그림으로만 설명된 부분, 끝까지 맞지 않은 단을 표시합니다. 사용자가 고치면 바로 다시 검산합니다.
7. **페이지 만들기.** 확정된 IR로 기호 도안, 3D, 단계별 안내를 만듭니다.

Claude API는 PDF의 각 쪽을 이미지와 추출한 글로 함께 읽고, 한 요청에 최대 600쪽까지 받습니다. 쪽마다 글 1,500에서 3,000 토큰과 이미지 최대 1,568 토큰이 듭니다 ([PDF support](https://platform.claude.com/docs/en/build-with-claude/pdf-support)). 3쪽 도안이면 호출 한 번의 PDF 입력은 약 1만 4천 토큰 이하입니다.

변환 한 번의 총비용은 되먹임 횟수에 따라 달라집니다. M2에서 실제로 재고, 그 값으로 무료 변환 개수를 정합니다.

## 그리는 엔진

네 가지 출력이 모두 IR과 코 사전에서 나오고, 프로토타입 코드가 출발점입니다. 3D만 도안마다 자동으로 되지 않아서 형태 템플릿 방식을 씁니다.

| 출력 | 만드는 방법 | 프로토타입에서 가져올 것 | 새로 만들 것 |
| --- | --- | --- | --- |
| 기호 도안 | 엔진이 단마다 코의 열 위치를 추적해 격자로 그림. 줄어든 자리는 "코 없음" 칸 | `model.py`의 열 추적, `chart.py`와 `symbols.py`의 기호 | 원통뜨기 표시, 코바늘 원형 차트 |
| 단계별 안내 | 단의 `ops`를 문장 조각으로 나눠 지금 뜨는 조각을 강조 | `gif.js`의 단 재생 화면 | GIF 파일 대신 화면에서 바로 재생 |
| 기호별 뜨는 법 | 코 사전의 항목마다 단계 애니메이션 1개 | `tut.js`의 기호 10가지 | 코바늘 기호. 도안에 나온 기호만 보여 주기 |
| 3D | 형태 템플릿을 고르고 IR의 코 수와 단 수로 치수를 정함 | 후드 템플릿(바라클라바), 진행 표시, 단수링 | 템플릿 추가: 평면 직사각형, 원통, 모자, 원판, 구 |

3D 템플릿은 LLM이 도안 설명을 보고 고르고, 확인 화면에서 사용자가 바꿀 수 있게 합니다. 맞는 템플릿이 없으면 3D 없이 기호 도안과 진행 표시만 제공합니다. 임의의 형태를 자동으로 3D로 만드는 것은 이번 범위가 아닙니다.

진행 위치는 모든 출력이 같은 값(단, 그 단에서 뜬 코 수)을 씁니다. 프로토타입처럼 3D와 기호 도안이 함께 움직입니다.

## 게이지

게이지는 선택이고, 도안마다 아래 세 상태 중 하나입니다. 재지 않은 사람은 도안 숫자 그대로 뜨고, 작업 화면에서 언제든 다시 맞출 수 있습니다.

| 상태 | 언제 | 페이지가 쓰는 숫자 |
| --- | --- | --- |
| 도안 숫자 그대로 | 게이지를 재지 않았거나, 재 보니 도안과 같음 | 원본 IR |
| 내 게이지로 다시 계산 | 재 보니 다르고, 지금 손땀으로 뜨고 싶음 | 원본에서 만든 파생 IR |
| 바늘을 바꿔 다시 재기 | 재 보니 다르고, 원단 느낌을 도안과 맞추고 싶음 | 다시 잴 때까지 원본 IR |

재기 번거로운 사람을 위한 장치는 세 가지입니다.

- 게이지 화면은 "재서 맞추기"와 "재지 않고 뜨기"를 같은 크기의 선택지로 보여 줍니다.
- 스와치 없이 뜨던 편물의 평평한 곳에서 10cm를 재서 넣을 수 있습니다.
- 재기를 권하는 문구는 옷이나 모자처럼 크기가 맞아야 하는 도안에만 띄웁니다. 구분은 IR의 완성 크기와 형태 템플릿으로 합니다.

다시 계산은 LLM 없이 엔진이 아래 순서로 합니다.

1. 코 수는 도안 코 수에 "내 코 게이지 ÷ 도안 코 게이지"를 곱하고, 구간의 `multiple`에 맞게 반올림합니다.
2. 늘림과 줄임의 횟수는 구간의 시작 코 수와 끝 코 수가 이어지도록 다시 정합니다.
3. 단 수로 적힌 구간은 단 게이지 비율로 조정하고, 겉면과 안면 순서가 유지되게 짝수로 맞춥니다.
4. 길이로 적힌 구간은 길이를 그대로 두고 예상 단수만 다시 계산합니다.
5. 결과를 엔진으로 다시 검산합니다. 통과하지 못하면 다시 계산을 제안하지 않고 바늘 바꾸기만 안내합니다.
6. 결과는 원본을 덮지 않고 파생 IR로 저장합니다. 사용자는 언제든 원본으로 돌아갈 수 있습니다.

예시로 바라클라바에 다른 게이지를 넣었을 때의 코 수, 단수, 완성 가로를 디자인 캔버스의 게이지 화면과 같은 규칙으로 계산해 두었고, M3의 테스트 값으로 씁니다. (구매한 도안에서 나온 숫자라 이 사본에는 적지 않았습니다. 값은 `private/balaclava.expected.json`에 있습니다.)

## 코바늘 지원

코바늘은 같은 IR, 엔진, 화면 위에 얹고, 대바늘과 다른 여섯 가지만 새로 만듭니다. 작업은 대바늘이 M3까지 끝난 뒤 M5에서 하지만, IR과 코 사전은 M0부터 코바늘을 담을 수 있게 둡니다.

| 다른 점 | 대바늘 | 코바늘 | 구현에 주는 영향 |
| --- | --- | --- | --- |
| 한 단의 구조 | 모든 코가 바늘에 걸려 있음 | 바늘에는 고리 1개. 뜬 코는 이미 완성됨 | 3D와 뜨는 법 그림에서 바늘 위의 코 표현이 다름 |
| 코의 높이 | 한 단의 코 높이가 같음 | 짧은뜨기, 한길긴뜨기처럼 코마다 높이가 다름 | 코 사전에 높이 값을 추가. 게이지는 무늬별로 잼 |
| 뜨는 방향 | 평면, 원통 | 평면, 닫는 원형, 나선 | `shape: 'spiral'`과 단 시작 기둥코 규칙 |
| 코를 넣는 자리 | 항상 다음 코 | 같은 코에 여러 번, 건너뛰기, 사슬 공간 | `Op.into`로 표현하고 검산이 이를 따라감 |
| 기호 도안 | 네모 격자 | 격자와 원형 차트 | 원형 차트 렌더러 추가 |
| 약어 체계 | k, p, k2tog 등 | US와 UK가 같은 약어를 다른 코에 씀 (US sc = UK dc) | 읽기 첫 단계에서 체계를 판별하고 확인 화면에 표시 |

M5에서 할 일은 다음과 같습니다.

- [ ] 코 사전에 코바늘 기본 코 추가: 사슬, 빼뜨기, 짧은뜨기, 긴뜨기, 한길긴뜨기, 늘림, 줄임
- [ ] 엔진: 원형과 나선 단의 코 수 검산, 기둥코를 코 수에 넣을지는 구간 설정으로 처리
- [ ] 기호 도안: 코바늘 기호와 원형 차트
- [ ] 3D 템플릿: 원판, 구, 원통
- [ ] 뜨는 법: 코바늘 기본 코 애니메이션
- [ ] 읽기: 약어 체계 판별과 코바늘 예시를 프롬프트에 추가

첫 번째로 지원할 코바늘 형태는 아직 정하지 않았습니다. 후보는 원형으로 뜨는 소품, 가방, 인형입니다.

## 마네킹 꾸미기와 유료화

유료 기능은 마네킹 꾸미기 하나입니다. 누구나 골라 볼 수 있지만 저장은 플러스만 되고, 저장 권한은 서버에서 확인합니다.

마네킹은 네 가지 값으로 저장합니다.

```ts
type Avatar = {
  face: 'default' | 'round' | 'slim' | 'square'
  skin: 'gray' | 'tone1' | 'tone2' | 'tone3' | 'tone4' | 'tone5'
  hair: 'none' | 'bangs' | 'bob' | 'long' | 'bun'
  glasses: 'none' | 'round' | 'horn' | 'half' | 'sun'
}
```

- 항목마다 목록 파일에 `tier: 'free' | 'plus'`를 적습니다. 무료 값은 기본 얼굴형, 회색, 머리 없음, 안경 없음입니다.
- 3D 부품은 단순한 도형으로 만듭니다. 프로토타입에서 구와 고리 도형으로 앞머리, 둥근 안경, 피부 톤을 얹어 보았습니다.
- "모자 벗은 모습"은 편물을 숨기는 보기 전환입니다.
- 미리보기는 브라우저에서만 바뀌고, 저장 요청에서 서버가 플러스 여부를 확인합니다.
- 플러스를 그만두면 마네킹은 기본 모습으로 보이고, 저장해 둔 꾸미기 값은 지우지 않습니다. 도안과 기록은 그대로 남습니다.

결제는 세 단계로 붙입니다.

1. M3까지는 가짜 결제(`BILLING_PROVIDER=mock`)로 플러스를 켜고 끕니다.
2. M4에서 결제 제공자를 정합니다. 사업자 형태에 따라 쓸 수 있는 곳이 다르므로, 국내 결제 대행사의 정기결제와 해외 결제 서비스를 비교합니다. 한국 사업자가 Stripe에 가입할 수 있는지부터 확인합니다.
3. 결제 결과는 `entitlements` 테이블 하나로 모으고, 앱은 이 테이블만 봅니다. 제공자를 바꿔도 앱 코드는 그대로입니다.

가격과 무료 변환 개수는 미정입니다. 변환 한 번마다 LLM 비용이 들기 때문에 무료 개수에는 상한이 필요합니다.

## 기록, 단수링, 계정 데이터

사용자 데이터는 아래 여덟 개 테이블에 두고, 도안에 딸린 것은 모두 소유자 한 명에게만 보입니다.

| 테이블 | 주요 필드 | 메모 |
| --- | --- | --- |
| `users` | id, 로그인 식별자 | 로컬은 고정 사용자 1명 |
| `patterns` | 소유자, 공예 종류, 제목, 상태, 원본 PDF 위치 | 상태는 읽는 중, 확인 필요, 준비됨 |
| `pattern_versions` | 도안, 종류(원본 또는 게이지 파생), IR JSON, 적용한 게이지 | 작업 화면은 현재 버전 하나를 가리킴 |
| `conversion_jobs` | 도안, 단계, 상태, 검산 결과, LLM 호출 수 | 올리기 화면의 진행 표시가 읽는 곳 |
| `progress_entries` | 도안, 기록 시각, 단, 뜬 코 수, 마무리 단계, 메모 | 프로토타입과 같은 구조 |
| `markers` | 도안, 단, 코 위치, 색, 이름 | 단수링 |
| `avatars` | 사용자, 꾸미기 값 | 사용자마다 1개 |
| `entitlements` | 사용자, 플랜, 기간 | 결제 결과만 기록 |

지킬 규칙은 세 가지입니다.

- 진행 위치는 "단과 그 단에서 뜬 코 수"로 저장합니다. 진행률은 저장하지 않고 IR의 총 코 수에서 계산합니다.
- 게이지를 다시 계산해 버전이 바뀌면 기록과 단수링을 새 버전의 같은 구간, 같은 비율 위치로 옮깁니다.
- 모든 읽기와 쓰기는 서버에서 소유자를 확인합니다. 도안 id를 알아도 다른 사람의 도안은 열리지 않습니다.

## 저작권과 개인정보

올린 도안은 올린 사람만 보고, 서비스는 도안 내용을 다른 사람에게 보여 주지 않습니다. 구매한 도안을 올리는 서비스이므로 이 원칙이 설계의 전제입니다.

- **공유 없음.** 공유 링크를 만들지 않습니다. 페이지, PDF, IR 모두 소유자만 엽니다.
- **비공개 저장.** PDF는 비공개 저장소에 두고, 서버가 소유자를 확인한 뒤에만 내려보냅니다.
- **함께 삭제.** 도안을 지우면 PDF, IR, 기록, 단수링을 함께 지웁니다.
- **LLM 전송 고지.** PDF는 읽기 단계에서 LLM 제공자에게 전송됩니다. 이를 이용 약관에 적고, 제공자의 데이터 보관과 학습 사용 조건을 출시 전에 확인합니다.
- **PDF는 신뢰하지 않는 입력.** LLM에는 도구를 주지 않고, 응답은 JSON 스키마와 엔진 검산을 통과한 것만 씁니다.
- **저장소에 실제 도안 금지.** 테스트에는 직접 쓴 도안만 커밋합니다. 실제 PDF와 프로토타입의 바라클라바 데이터는 git에서 제외한 폴더에 둡니다.

출시 전에 법률 검토를 받습니다. 디자이너와 협업해 공식 변환을 제공하는 것은 이후 과제입니다.

## 로컬 개발 환경과 저장소 구조

로컬에서는 설치, 개발 서버, 테스트 명령 세 개로 전체가 돌아야 합니다. 바깥 계정은 LLM API 키 하나만 필요합니다.

```text
tteobogi/
  apps/web/               Next.js 앱. 화면, API, 변환 워크플로
  packages/pattern-ir/    IR 타입, JSON 스키마, 코 사전
  packages/engine/        코 수 검산, 게이지 재계산
  packages/reader/        PDF 읽기, LLM 프롬프트, 되먹임 반복
  packages/render-chart/  기호 도안 (SVG)
  packages/render-3d/     형태 템플릿과 three.js 매핑
  packages/tutorials/     기호별 뜨는 법
  fixtures/               직접 쓴 테스트 도안과 기대 결과
  private/                실제 PDF와 프로토타입 데이터 (git 제외)
  prototype/              지금까지의 프로토타입 소스 (참고용, git 제외)
  docs/PLAN.md            이 계획서의 사본
```

| 명령 | 하는 일 |
| --- | --- |
| `pnpm install` | 의존성 설치 |
| `pnpm dev` | 앱, 로컬 데이터베이스, 로컬 워크플로를 함께 실행 |
| `pnpm test` | 엔진, 게이지, 렌더러 테스트 |
| `pnpm reader private/도안.pdf` | PDF 한 개를 읽어 IR과 검산 결과를 출력 |

환경 변수는 `ANTHROPIC_API_KEY`, `DATABASE_URL`, `STORAGE_DIR`, `AUTH_MODE`, `BILLING_PROVIDER` 다섯 개입니다. 로컬 기본값은 `.env.example`에 둡니다.

프로토타입 파일은 아래처럼 옮깁니다. Python 코드는 TypeScript로 다시 씁니다. 엔진과 렌더러가 브라우저와 서버 양쪽에서 돌아야 하기 때문입니다.

| 프로토타입 파일 | 내용 | 옮겨 갈 곳 |
| --- | --- | --- |
| `model.py` | 바라클라바를 한 코씩 따라가는 모델과 코 수 검산 | `engine`, 그리고 `private/`의 바라클라바 IR |
| `symbols.py`, `chart.py` | 기호 모양과 전체 기호 도안 | `render-chart` |
| `site/index.html` | 3D 매핑, 진행 표시, 단수링, 기록, 도안 위 표시, 확대와 축소 | `render-3d`와 `apps/web` |
| `site/tut.js` | 기호 10가지의 단계 애니메이션 | `tutorials` |
| `gif/gif.js` | 단계별 안내 화면 | `apps/web`의 단계별 안내 |

## 테스트와 완료 기준

엔진과 게이지는 고정된 숫자로, 읽기는 녹화한 LLM 응답으로 테스트합니다. LLM을 부르지 않고도 전체 테스트가 돌아야 합니다.

| 대상 | 테스트 | 통과 기준 |
| --- | --- | --- |
| 엔진 | 바라클라바 IR 검산 | 전체 단수와 코 수 흐름이 `private/`의 기대값과 같음 |
| 게이지 | 다른 게이지로 다시 계산 | 코잡기, 머리 코 수와 길이 구간 단수가 `private/`의 기대값과 같음. 다시 검산 통과 |
| 게이지 | 임의 게이지 여러 개 | 다시 계산 뒤 검산 통과. 완성 가로가 도안과 1코 폭 이내 |
| 게이지 | 건너뛰기 | 원본 IR이 그대로 쓰이고, 나중에 다시 맞추기가 열림 |
| 읽기 | 고정 PDF와 녹화한 LLM 응답 | 같은 IR이 나옴. 검산 실패 때 되먹임이 동작 |
| 기호 도안 | SVG 스냅샷 | 프로토타입 도안과 칸 단위로 일치 |
| 3D | 템플릿별 정점 수와 경계 상자 | 값이 고정 범위 안 |
| 화면 | 브라우저 자동 테스트 | 올리기, 확인, 게이지 건너뛰기, 기록, 단수링 달기가 끝까지 됨 |
| 접근성 | 키보드 조작과 글자 대비 | 모든 조작이 키보드로 되고, 본문 대비가 4.5:1 이상 |

읽기 품질은 테스트 도안 묶음으로 따로 잽니다. 묶음의 크기와 목표 통과율은 M2에서 정합니다.

## 위험과 아직 정하지 않은 것

가장 큰 위험은 읽기 정확도와 3D의 범위입니다. 둘 다 틀릴 수 있다는 점을 화면에서 드러내고 사용자가 고칠 수 있게 해서 대응합니다.

| 위험 | 일어나면 | 대응 |
| --- | --- | --- |
| LLM이 도안을 잘못 읽음 | 틀린 기호 도안을 따라 뜨게 됨 | 엔진 검산, 되먹임, 확인 화면. 도안에 코 수가 적혀 있지 않은 구간은 "확인 필요"로 표시 |
| 3D 템플릿이 도안과 안 맞음 | 3D가 실제 모양과 다름 | 사용자가 템플릿을 바꾸거나 끌 수 있게 함. 3D는 참고용이라고 표시 |
